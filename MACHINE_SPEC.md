# Machine Specification v0.1

<p class="lede">This document turns the finite mathematical world into one executable primitive experiment. It does not alter the fixed structure. It freezes the event grammar used to score history.</p>

## Status

**Version:** 0.1  
**Purpose:** primitive adjacent-level historical test  
**Recursion depth:** 1 child generation for local invalidation  
**Continuation:** disabled  
**TOTAL / SMA filters:** disabled  
**Rate filters:** disabled  
**Optimization:** prohibited inside this version

Any change to the rules below creates a new machine version.

## 1. Eligible decision level

A decision level is an explicitly selected parent level `Li` with immediate neighbours `Li-` and `Li+`.

For Experiment 1, eligible levels are the internal canonical parent levels that have both neighbours available.

The machine does not invent, move or optimize a level.

## 2. Local geometry

For each decision level:

```text
Li- < Ci- < Li < Ci+ < Li+
```

where:

```text
Ci- = Li- * (Li / Li-)^0.786
Ci+ = Li  * (Li+ / Li)^0.236
```

The two virtual hypotheses are:

```text
H+ : Li -> Li+
H- : Li -> Li-
```

with:

```text
H+ invalidation = Ci-
H- invalidation = Ci+
```

## 3. Authoritative historical data

The primitive test uses one-minute OHLCV data where available.

A structural boundary is considered **touched** when it lies inside the candle range:

```text
low <= boundary <= high
```

A close beyond the level is not required in v0.1.

This is an experimental convention, not a statement about what a market crossing fundamentally is.

## 4. Entry event

While `Li` is armed, the first one-minute candle whose range contains `Li` starts a decision event.

The theoretical entry price for both virtual hypotheses is exactly `Li`.

At entry:

```text
state = BOTH_ACTIVE
long_entry  = Li
short_entry = Li
```

No slippage is applied to the structural result. Execution-cost scenarios are applied separately to economic results.

## 5. Commitment / first resolution

From `BOTH_ACTIVE`:

- first valid touch of `Ci+` invalidates `H-` and leaves `H+` alive;
- first valid touch of `Ci-` invalidates `H+` and leaves `H-` alive.

Therefore:

```text
BOTH_ACTIVE + Ci+ -> UP_SURVIVES
BOTH_ACTIVE + Ci- -> DOWN_SURVIVES
```

If a single one-minute candle contains both `Ci-` and `Ci+`, event ordering is unknowable from OHLC and the event becomes:

```text
UNRESOLVED_COMMITMENT
```

No path is invented.

## 6. Survivor resolution

After `Ci+` occurs first:

```text
UP_SURVIVES
target = Li+
failure = Ci-
```

After `Ci-` occurs first:

```text
DOWN_SURVIVES
target = Li-
failure = Ci+
```

The survivor therefore either reaches the adjacent parent target or later reaches its opposite child-yellow invalidation boundary.

If target and failure are both contained in the same one-minute candle and their order cannot be inferred from prior candles:

```text
UNRESOLVED_SURVIVOR
```

Again, chronology is not guessed.

## 7. Completion states

A resolved event ends in exactly one of:

```text
UP_TARGET
UP_FAILURE
DOWN_TARGET
DOWN_FAILURE
UNRESOLVED_COMMITMENT
UNRESOLVED_SURVIVOR
```

A target is not automatically a continuation trade in v0.1.

Every completed event returns the portfolio state to `FLAT`.

## 8. Rearm rule

After any completed or unresolved event at `Li`, that decision level becomes **disarmed**.

It cannot generate another event until market price subsequently touches either adjacent parent:

```text
Li- or Li+
```

After that parent touch, `Li` is rearmed and the next later touch of `Li` may begin a new event.

This rule prevents an arbitrary number of overlapping decisions from being generated by local oscillation around one level.

It is an experimental convention of v0.1 and can be challenged in a later version.

## 9. Gaps and rapid traversal

Crypto trades continuously but historical sampling can still skip visible intermediate chronology.

If a candle opens beyond one or more relevant boundaries:

- score only ordering that is logically established by prior candle state;
- if more than one mutually exclusive event could have occurred between observations, mark the event unresolved;
- never assume a straight-line path between closes.

## 10. Price source

The historical structural test uses the OHLCV trade series of the selected instrument and venue.

Mark price, index price and liquidation engine prices are outside the primitive structural score.

A later execution study may replace the price source, but that creates a different execution specification.

## 11. Two-direction implementation

The historical test uses **two independent virtual books**.

At `Li`:

```text
virtual long  = 1 normalized unit
virtual short = 1 normalized unit
```

They are scored independently until one is invalidated.

This preserves the intended geometry without assuming a venue supports simultaneous hedge-mode positions.

Live hedge mode, subaccounts and netted accounts are execution implementations, not changes to the structural machine.

## 12. Returns

Use log return for structural comparability.

For a long leg from entry `E` to exit `X`:

```text
r_long = ln(X / E)
```

For a short leg:

```text
r_short = ln(E / X)
```

The event gross result is the sum of the two virtual-leg results.

Report the survivor leg, sacrificed leg and combined event separately.

## 13. Cost layers

Do not collapse costs into one opaque figure.

Report:

```text
structural result
gross trading result
net after fees
net after fees + spread/slippage
net after fees + spread/slippage + funding
```

Experiment 1 should run a friction sensitivity rather than pretend one exchange fee schedule is universal.

Required round-trip friction scenarios per executed leg:

```text
0 bps
5 bps
10 bps
20 bps
```

Funding is recorded separately when the underlying dataset provides it. If funding data are unavailable, the result must be labelled:

```text
funding_not_modelled
```

not silently treated as zero.

## 14. Flat time and exposure states

Track calendar time in:

```text
FLAT
BOTH_ACTIVE
UP_SURVIVES
DOWN_SURVIVES
UNRESOLVED
```

Report:

```text
flat_fraction
discovery_fraction
directional_exposure_fraction
unresolved_fraction
```

`BOTH_ACTIVE` is economically active but approximately direction-neutral before one hypothesis dies.

## 15. No trailing rule in the primitive test

The broader project proposes structural stop advancement after later structural crossings.

That rule is not part of Machine v0.1.

The primitive experiment stops at one adjacent parent target or survivor failure.

Trailing and continuation are separate experiments because otherwise they contaminate the answer to the first question.

## 16. Deterministic transition table

```text
FLAT
  + armed touch Li
  -> BOTH_ACTIVE

BOTH_ACTIVE
  + Ci+ first
  -> UP_SURVIVES

BOTH_ACTIVE
  + Ci- first
  -> DOWN_SURVIVES

BOTH_ACTIVE
  + Ci+ and Ci- same unresolved candle
  -> UNRESOLVED_COMMITMENT

UP_SURVIVES
  + Li+ first
  -> UP_TARGET -> FLAT

UP_SURVIVES
  + Ci- first
  -> UP_FAILURE -> FLAT

DOWN_SURVIVES
  + Li- first
  -> DOWN_TARGET -> FLAT

DOWN_SURVIVES
  + Ci+ first
  -> DOWN_FAILURE -> FLAT

SURVIVOR
  + target and failure same unresolved candle
  -> UNRESOLVED_SURVIVOR -> FLAT
```

## 17. What v0.1 is testing

The first experiment asks:

> **Given the fixed ladder and this frozen event grammar, does the complete two-hypothesis local decision process have useful structural resolution and positive net expectancy under realistic friction?**

It does not ask whether the structure itself is true.

It does not ask whether TOTAL predicts the trade.

It does not optimize the ladder.

It tests the machine.
